从疑问到理解：目标检测 AP 指标学习笔记

在阅读 RGB–Thermal 微小目标检测论文 ProG-Net 时，我遇到了一串看似简单、实际很容易混淆的问题：AP、AP50、AP75 到底有什么区别？匹配阈值是什么？一个与真实目标完全不重合的预测框，为什么还要参与计算？双模态模型的结果为什么又分成 Visible 和 Thermal？

这篇文章整理了我沿着这些问题逐步理解 AP 的过程。先从一次检测怎样判对错讲起，再手算一个 AP50，最后回到数学定义和论文结果表。后面的数字例子均为教学示例，不是论文实验结果。

1. 先弄清楚：模型究竟输出了什么？

目标检测模型通常为每个预测输出三项信息：边界框、类别、置信度。

例如：模型输出一个框，类别为“汽车”，置信度为 0.90。这只表示模型给这个预测打了一个较高的分数，并不意味着它真的找到了汽车，也不保证这个分数就是经过校准的正确概率。

评价时，还需要真实标注，即 Ground Truth，简称 GT。将预测与 GT 比较后，才能知道预测是否正确。

名称 含义 汽车检测中的例子
TP，True Positive 正确检测 类别正确，位置达标，成功匹配一辆真实汽车
FP，False Positive 误检 背景被报成汽车、框偏得太远，或者重复报告同一辆车
FN，False Negative 漏检 一辆真实汽车没有被任何有效预测匹配

本文先讨论普通标注下的一对一匹配，不展开 crowd、ignore 等特殊规则。对于目标检测，背景没有自然、有限的“所有负样本框”集合，因此 AP 通常不依赖 TN（真负例）计数。

2. 我的第一个疑问：匹配阈值是什么？

匹配阈值规定了预测框与真实框要有多接近，才能算一次正确检测。

常用的匹配度量是 IoU（Intersection over Union，交并比）：

IoU 为 1 表示完全重合，为 0 表示没有面积上的重叠。

假设模型的类别预测正确，预测框与某个尚未匹配的真实框 IoU 为 0.60：

匹配阈值 比较 是否达到位置要求
0.50 0.60 ≥ 0.50 是
0.75 0.60 < 0.75 否

此外，普通检测评价还要求：预测只能匹配同一张图中的同类别目标，一个普通 GT 最多被一个预测匹配。 多个预测框围住同一辆车，不能算找到了多辆车。

我最容易混淆的两个阈值

阈值 用什么比较 回答的问题
置信度阈值 模型输出的分数 要保留哪些预测？
匹配阈值 IoU 等匹配分数 一个预测能不能算正确？

因此，AP50 中的 50 指匹配阈值 0.50，不是置信度 50%。 下面的计算先固定使用 IoU；如果协议改用 SAFit，就需要用 SAFit 分数判断匹配，不能继续把 50 解释成 IoU 阈值。

3. Precision 和 Recall 分别在问什么？

精确率 Precision 关注“报出来的结果有多可靠”，召回率 Recall 关注“真实目标找到了多少”：

例如，真实有 10 辆车，模型报出 8 个车框，其中 6 个正确：

  • Precision = 6/8 = 75%。
  • Recall = 6/10 = 60%。

只报最有把握的一辆车，可能精确率很高，却漏掉很多目标；大量报框，可能找到更多目标，也可能带来大量误检。因此，只看其中一个数不够。

AP 的思路是观察一系列置信度门槛下的 Precision 与 Recall，而不是只评价某一个门槛。

4. 我的第二个疑问：一个模型的 AP50 到底怎么算？

先只考虑“汽车”一个类别。假设整个测试集有 3 辆真实汽车，记为 A、B、C。

固定 IoU 匹配阈值为 0.50，将模型提交评价的汽车预测按置信度从高到低排列：

预测 置信度 匹配情况 判断
① 0.95 与 A 的 IoU = 0.80 TP
② 0.90 预测在背景上，与所有 GT 的 IoU = 0 FP
③ 0.80 与 B 的 IoU = 0.60 TP
④ 0.70 与 A 的 IoU = 0.70，但 A 已被①匹配 FP，重复检测
⑤ 0.60 与 C 的 IoU = 0.55 TP

这里将匹配关系设置得很简单，不存在多个候选 GT 的竞争。实际评价通常先在各图、各类别内按分数进行匹配，再汇总整个测试集同一类别的预测排序；不能跨图片匹配，也通常不是先计算每张图的 AP 再平均。

依次纳入这些预测，相当于逐渐降低置信度门槛：

保留的预测 累计 TP 累计 FP Precision Recall
① 1 0 1 1/3
①② 1 1 1/2 1/3
①②③ 2 1 2/3 2/3
①②③④ 2 2 1/2 2/3
①②③④⑤ 3 2 3/5 1

这些点构成 Precision–Recall 曲线，简称 P–R 曲线，横轴是 Recall，纵轴是 Precision。

每加入一个 TP，召回率就增加；每加入一个 FP，召回率不变，当前精确率下降。最后一行虽然有 Precision = 60%、Recall = 100%，**但 AP50 既不是 60%，也不是 100%**，因为它还要考虑前面的整条曲线。

5. 我的第三个疑问：②的 IoU 为 0，为什么也参与计算？

我起初把“匹配不成功”理解成了“不参与评价”。实际上，匹配不成功正是误检需要被记录的原因。

如果评价时先删掉所有 IoU 不达标的框，模型到处乱报也不会受到相应惩罚。评价会失去衡量误检的能力。

这里还要补充一个细节：计入 FP 不等于每个 FP 都必然使最终 AP 数值下降。 如果模型已经找全所有目标，之后才出现一些低分 FP，精确率包络可能使 AP 保持不变。例子中的②出现在后续 TP 之前，会压低后续召回位置能达到的精确率，因而影响 AP。

6.4 COCO 为什么会算出略有不同的数字？

COCO 使用 101 个召回率位置的插值精确率均值：

即在 0、0.01、0.02、……、1 这些位置采样。对于本例：

  • 0 至 0.33：34 个点，精确率取 1。
  • 0.34 至 0.66：33 个点，精确率取 2/3。

因此，75.56% 与 75.64% 分别对应分段面积和 101 点采样。本例中二者很接近，但不是完全相同的定义。COCO 的默认采样和累计过程可以在官方评价代码中核对。

不同评价器还可能采用其他 AP 约定。复现论文时，应使用对应评价器；不能只凭“P–R 曲线面积”几个字自行选择积分算法。

7. 回到最初的问题：AP、AP50、AP75 和 mAP 有什么区别？

前面算的是单类别、单匹配阈值的 AP。为了把几种平均区分开，记 AP(c, τ) 为类别 c、匹配阈值 τ 下的 AP。

指标 常见含义
单类别 AP50 某一类别在阈值 0.50 下的 AP
mAP50 所有有效类别的 AP50 取平均
论文表格中的 AP50 经常就是跨类别平均后的 mAP50
AP75 常指阈值 0.75 下跨类别平均的 AP
COCO 风格 AP / mAP50–95 再对 0.50、0.55、……、0.95 共 10 个匹配阈值平均

若有 C 个有效类别：

每换一个匹配阈值，都要重新判断匹配并计算 AP。不是先算出 AP50，再乘一个系数得到 AP75 或整体 AP。COCO 默认阈值设置可见官方实现。

比如汽车 AP50 为 80%，行人 AP50 为 60%，两类的 mAP50 为 70%。通常这是类别等权平均，不是按各类别目标数量加权。

“AP”这个简称本身并不能告诉我平均了哪些维度。 我需要结合论文的指标定义，确认是否跨类别、跨阈值，以及采用何种匹配度量。

8. APet、APt、APS、APM、APL 又是什么？

这些下标表示目标尺度：它们关注的是在指定大小的目标上，模型表现如何。

令真实框面积 A = w×h，等效边长为 √A。RGBT-Tiny 数据集原论文 §III-B将尺度划分为：

指标 含义 面积范围 等效边长范围，像素
APet Extremely tiny，极微小目标 [1², 8²) [1, 8)
APt Tiny，微小目标 [8², 16²) [8, 16)
APS Small，小目标 [16², 32²) [16, 32)
APM Medium，中目标 [32², 96²) [32, 96)
APL Large，大目标 [96², +∞) [96, +∞)

这里按原论文记录为左闭右开区间。原聊天曾引用后续论文给出另一套边界写法，整理时应以原始定义为准；实际边界目标怎样归组，还需要核对使用的评价代码。

分组依据是面积，不要求宽和高都处在对应区间。例如 4×16 的框面积为 64，等效边长为 8，按上表属于 tiny。

还需要记住三点：

  1. RGBT-Tiny 的 small 已经细分，不能直接套用 COCO 中包含更小目标的 small 定义。
  2. 尺度 AP 通常继续跨类别、跨匹配阈值平均；尺度外目标及预测的忽略规则应交给评价器处理，不能随意删除所有尺度外预测。
  3. 整体 AP 不能由这五个尺度 AP 简单平均得到。 各分组的排序、有效类别和忽略规则可能不同。

9. 为什么微小目标还需要 SAFit？

读到这里，我才发现：理解 AP 的汇总方法，还不等于理解“正确匹配”的标准。

IoU 对微小框的位置偏移尤其敏感。假设预测框和真实框大小相同，只水平错开 2 像素：

框大小 交集面积 并集面积 IoU
8×8 6×8 = 48 64+64−48 = 80 0.60
80×80 78×80 = 6240 6400+6400−6240 = 6560 约 0.951

同样的绝对偏移，对小目标会造成大得多的 IoU 下降。RGBT-Tiny 提出的 SAFit（Scale Adaptive Fitness）通过尺度自适应地组合 IoU 与 NWD，兼顾不同尺度的匹配表现。其设计见原论文 §III-C。

10. 我的延伸疑问：双模态模型为什么分别报告 Visible 和 Thermal？

我当时问：“这个模型不是 visible + thermal 的吗？为什么测试时 visible 与 thermal 分开？”随后又追问：“这是一个双模态融合的模型，怎么进行单模态测试？”

关键是把三件事分开：输入什么图像、使用什么标注训练、对照什么标注评价。

双模态输入并不要求两种图像使用完全相同的目标框。RGB 与热红外图像即使经过配准，也可能存在局部视差或目标边界差异。RGBT-Tiny 提供两套模态标注，其数据和实验设定见数据集论文。

在原讨论所涉及的 ProG-Net 主实验中，Visible / Thermal 应结合相应标注体系理解，不能看到 Visible 列就推断“只输入 RGB”。但原讨论也指出：论文关于分别训练与标注切换的描述关系不够清楚，尚不能断定两列一定是同一套权重、同一批预测分别评分。这里保留疑问，不将示意性的解释写成已确认的实现细节。

实验情形 需要明确的设置
双模态输入，按 Visible 标注评价 输入仍为 RGB + Thermal，评价参照 RGB 标注
双模态输入，按 Thermal 标注评价 输入仍为 RGB + Thermal，评价参照热红外标注
单模态基线 单模态结构或明确规定的输入方式，通常需对应训练
模态缺失测试 保留双模态网络，明确怎样屏蔽或替代缺失输入

将一路输入置零，是一种需要定义的缺失模态实验；它不会自动变成一个公平训练的单模态基线。同一张表中的不同方法，也可能采用不同输入方式，必须逐行核对。论文入口：ProG-Net。

11. 哪些因素会影响这些指标？我该怎样读实验结果？

AP 最终来自“匹配判定 + 分数排序 + 汇总”，因此影响因素不只在网络结构里。

因素 对指标的可能影响
漏检 最大召回率不足，降低 AP
高置信度误检 排在真阳性之前，压低相关召回位置的精确率
分类错误 预测类别计入 FP，真实类别目标可能成为 FN
定位误差 在严格匹配阈值下无法成为 TP，常体现在 AP75 上
置信度排序 相同预测框集合，排序不同也可能得到不同 AP
输入分辨率、下采样和特征融合 影响微小目标是否保留足够信息
跨模态错位、标注偏差 对 APet、APt 和严格定位评价尤其敏感
NMS 与候选框数量限制 可能去掉重复误检，也可能误删密集目标
测试划分和目标数量 改变评价难度；样本稀少的尺度结果可能波动较大

降低置信度门槛不保证 AP 一定提高。AP 本来就考察多个分数位置；过早过滤低分预测可能丢掉有效 TP，而保留更多 FP 的影响取决于它们的位置。实际评价还受候选数量等设置约束。

看论文表格时，我现在会作这样的判断：

  • AP50 提高、AP75 没提高：可能改善了检出，却没有同步改善精细定位，需要进一步检查错误类型。
  • APet、APt 提高：支持微小目标分组表现改善，但还不能单凭分数断定是哪个模块、哪种机制起作用。
  • APL 很高：需要同时查看大目标数量和结果稳定性。
  • 两篇论文数字差距很大：先核对数据划分、输入模态、评价标注、IoU / SAFit、输入尺寸和评价器配置，再讨论模型优劣。

对于视频来源的数据集，还应核对划分单位。相邻帧可能非常相似，随意把同一序列拆到训练和测试两边，会影响成绩的可信度。这是原聊天中“为什么文件夹里有很多重复图片”这个问题与评价指标的连接点。

12. 我最后形成的理解

最初我以为 AP 就是某种“正确率”，后来才发现它描述的是一个更完整的过程：

对我帮助最大的三个认识是：匹配阈值与置信度阈值有不同职责；误检必须参与评价；表格里的 AP 必须连同完整评价协议一起理解。

下次再遇到一个 AP 数字，我会先问：它评价的是哪些目标，依据哪套标注，怎样判定匹配成功，又在哪些维度上做了平均？把这些问题回答清楚，数字才有可以比较的含义。
